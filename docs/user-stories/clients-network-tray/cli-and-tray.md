## M. 原生终端、CLI 与本机控制面

| 编号 / 功能                 | User story                                                                                                                                         | 验收要点                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-M01 从本地终端启动       | 作为终端使用者，我希望用 `webmux run -- COMMAND ARG...` 创建并附着会话，或引用 Web 端保存的启动配置，以便保留原来的 CLI 工作习惯并随时转到浏览器。 | `--` 后 argv 原样传递；`--launch-config NAME`（`--config-id` 别名）按 Web 端显示的唯一名称选择已保存配置，以服务端保存的 argv 与环境变量创建，名称不存在时以用法错误退出并列出已有名称，且与命令、`--env` 互斥；默认当前目录，可指定名称与目录；`--detach` 只创建并输出 ID 和无 token 本机链接；默认附着前向 stderr 公告会话入口，stdout 保留给会话；非 TTY 的附着请求在创建前拒绝；会话进程默认看到 WebMux 的虚拟终端身份（`TERM_PROGRAM=webmux` 及服务版本），不会继承 Kitty 等宿主终端身份，启动配置显式提供的终端变量仍可覆盖默认值。引用勾选了混合模式的配置时创建从终端开始的混合会话（US-Q13）。 |
| US-M02 显式传递运行环境     | 作为进阶使用者，我希望指定启动目录和必要环境变量，以便让程序使用正确项目与工具环境。                                                               | `--cwd` 使用服务器目录规则；Linux/macOS 的 `webmux run -- COMMAND` 默认继承调用方 shell 的环境（跳过 `TERM`、宿主终端身份、`WEBMUX_SESSION_ID`、`PWD`/`OLDPWD` 与不合法名称），重复 `--env NAME=VALUE` 在其上覆盖；Windows 客户端与启动配置不继承调用方环境；未发送的变量来自服务环境；普通网页创建与本机 CLI 的环境传递权限按接口约定处理。                                                                                                                                                                                                                                                            |
| US-M03 附着与观察           | 作为使用者，我希望 `webmux attach ID` 回到已有 PTY，或只观察，以便在手机和原生终端间接续同一任务。                                                 | 初次附着完整回放并进入原始终端模式；默认取得控制并同步尺寸，`--observe` 不输入或改尺寸；程序已开启明暗报告（DEC 2031）时，取得控制后按本地终端背景色（OSC 11）报告明暗，使程序改用本地终端配色；会话退出时返回其退出码；服务未运行返回 3，不自动拉起服务；结束后恢复控制台状态；取消、会话退出或断线会中断无输入时的终端读取，`Run` 返回前等待输入、输出与尺寸协程退出，不关闭 stdin，也不终止持久会话；Unix 的 poll/read 遇到信号中断时重试，不误判为终端关闭。混合会话在聊天端、休眠或切换中拒绝附着并以 1 退出；附着期间被切到聊天视为被动分离，以 0 退出（US-Q13）。                                |
| US-M04 分离与重新接管       | 作为原生终端使用者，我希望浏览器接管后本地按键不会误抢控制，并可明确接管或分离，以便安全切换设备。                                                 | 被接管后显示控制提示，丢弃普通键及终端自动应答；Enter 仅接管、不发给会话；Ctrl+] 分离且进程继续运行，返回 0；兼容 modifyOtherKeys、kitty 与 Windows 编码按键，退出时关闭临时上报模式。                                                                                                                                                                                                                                                                                                                                                                                                                  |
| US-M05 命令行发现与打开会话 | 作为使用者，我希望用 `ls` 列出会话并用 `open ID` 获取入口，以便不经过首页就能找到目标。                                                            | `ls` 显示 ID、名称、状态、命令和目录，`--json` 输出原始会话数组；`open` 校验目标并打印不含 token 的本机链接，`--browser` 可打开默认浏览器。`ls` 为混合会话在状态列附加所在端，`--json` 原样包含 `hybrid`（US-Q13）。                                                                                                                                                                                                                                                                                                                                                                                    |
| US-M06 诊断运行实例         | 作为部署者，我希望用 `status` 看到健康状态、访问地址和配置漂移，以便确认正在使用哪个实例。                                                         | 优先本机 API，必要时使用运行时记录与 TCP 健康检查；区分运行、未运行、无响应或错误并给出退出码；`--json` 提供版本化结果，只有同时 `--reveal-token` 才揭示 token；提示 listen/token 配置与运行实例的差异。                                                                                                                                                                                                                                                                                                                                                                                                |
| US-M07 停止指定实例         | 作为部署者，我希望可靠地停止自己启动的服务，以便清理后台运行实例。                                                                                 | `stop` 优先经本机控制面关闭，必要时验证运行记录后退回 SIGTERM 和超时 SIGKILL；无记录不随意发信号；systemd/launchd 实例默认要求使用服务管理命令，显式 `--force` 可覆盖；支持超时与 JSON 结果。                                                                                                                                                                                                                                                                                                                                                                                                           |
| US-M08 本机桥接与权限边界   | 作为本机使用者，我希望 CLI 和 Windows 桥接无需维护网络 token，以便直接访问当前用户的服务。                                                         | Unix 套接字验证同用户身份，`bridge` 在标准输入输出间传输；浏览器网络入口仍要求认证；会话内进程不能用本机管理 API 读取 token、停止服务或控制隧道，也不能经套接字读取或修改 `/api/tunnel` 及其子路径（403）；套接字不是不同账号间的共享授权机制。                                                                                                                                                                                                                                                                                                                                                         |

## O. Windows/WSL 托盘管理

| 编号 / 功能                        | User story                                                                                                                                         | 验收要点                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-O01 安装或升级 WSL 服务         | 作为 Windows 使用者，我希望从托盘显式安装或升级 WSL 中的 WebMux，以便减少手工下载步骤。                                                            | WSL 中的 webmux 缺失、缺少本机 API、控制契约过旧或版本低于托盘时提供入口；WSL 2 与发行版可用时选择匹配架构和托盘版本；校验发布时嵌入的服务摘要才安装；托盘下载缓存中已有同版本且摘要匹配的文件（包括 Windows 安装程序预置的服务端）时直接安装、不联网，摘要不符时丢弃并重新下载；支持 GitHub 与镜像回退；不静默自动安装；普通本地托盘构建无摘要时不提供安装；运行中的旧服务到重启才更新。                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| US-O02 启动方式与恢复              | 作为 Windows 使用者，我希望托盘管理 WebMux 的启动和故障恢复，以便无需一直开着 WSL 窗口。                                                           | 可选 auto、tray、systemd；auto 优先已有可用用户服务，否则托盘托管；按方式保持 WSL 存活；托盘托管意外退出后退避重启，10 分钟内最多 5 次；systemd 重启策略交给单元。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| US-O03 管理所属实例                | 作为 Windows 使用者，我希望托盘区分自己管理的服务和外部实例，以便不误停其他终端启动的工作。                                                        | 可启动、停止、重启所属实例；有会话的停止、重启或切换目标先确认；外部或启动方式不符的实例只提供访问操作；不擅自接管停止权限。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| US-O04 登录启动与单实例            | 作为 Windows 使用者，我希望登录后出现一个托盘实例，以便随时找到服务入口。                                                                          | 同一 Windows 用户只运行一个托盘，再次启动通知已有实例；可选择注册当前 exe 为登录启动；exe 移动后需重新登记；安装程序可登记同一启动项，复选项随之显示为已勾选；`webmux-tray.exe quit` 请求已运行的托盘按“仅退出托盘”退出且不询问，退出码 0 表示已退出或未运行、1 表示仍在运行、2 表示参数错误，`--kill-path` 超时后只结束当前用户从该路径运行的托盘；无需以管理员启动托盘。                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| US-O05 选择发行版与编辑设置        | 作为 Windows 使用者，我希望选择 WSL 发行版、启动方式和路径，以便使用自己配置的开发环境。                                                           | 设置写入 `%APPDATA%\WebMux\tray.json`，保存后自动重载；无效文件提示并使用默认值，不覆盖文件；提供打开 WebMux 配置与托盘设置入口；配置缺失才提供初始化，已有配置不被自动改写。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| US-O06 查看状态和日志              | 作为 Windows 使用者，我希望托盘图标、菜单和日志解释运行问题，以便判断该重启还是修正配置。                                                          | 区分运行、启动、停止和错误；提示 WSL 缺失、版本不兼容（见 US-O11）、配置及健康错误；可打开服务日志或 systemd journal 和托盘日志；托盘日志轮转且不记录 token。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| US-O07 诊断 Windows 可达性         | 作为 Windows 使用者，我希望知道 WSL 内服务健康但 Windows 仍无法连接的情况，以便定位网络模式或 localhost 转发问题。                                 | 独立从 Windows 回环地址检查可达性，不带 token 且不走系统代理；故障时提示 localhostForwarding/networkingMode；不把 WSL 内健康等同于 Windows 浏览器可达。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| US-O08 转发可信远程地址            | 作为 Windows 使用者，我希望在 NAT 模式下通过选定的主机地址访问 WSL 服务，以便从手机继续操作。                                                      | 转发默认关闭，Tailscale 地址优先展示；仅服务健康、配置 token 且 Windows 可达时监听，条件失效暂停、恢复后继续；转发 HTTP 与 WebSocket 并校验地址对应 Host；服务报告网络开放状态时，未开放（回环监听会拒绝局域网 Host）则提示先开启 US-O13 的开关；保存地址选择并报告端口冲突，退出托盘即停止；不自动修改防火墙。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| US-O09 打开和复制受保护入口        | 作为 Windows 使用者，我希望从托盘打开页面、在统一的“复制链接”子菜单中复制本机/远程/经托盘转发/公网链接，或复制 token，以便把访问入口带到另一设备。 | 操作时从 WSL 获取 token，不在 Windows 配置中保存；复制链接可带 `#token=`，不配置 token 时复制普通链接；仅服务明确返回 `settingsAvailable: true` 时提供“公网访问设置”，打开本机 `/settings/tunnel` 并沿用 token 片段交接；敏感剪贴板排除历史和云同步，60 秒后仅在内容未被替换时清空；通知只显示无 token 地址。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| US-O10 退出托盘保留任务            | 作为 Windows 使用者，我希望只退出托盘而保留 WebMux，以便临时关闭桌面客户端却不中断任务。                                                           | “仅退出托盘”不停止服务，重新打开后恢复可用控制；托盘转发随退出停止；Windows 注销或关机不承诺保留任务；需要停服务时使用单独停止操作。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| US-O11 判断 WSL 服务兼容与版本对应 | 作为 Windows 使用者，我希望托盘告诉我它与 WSL 中的 webmux 是否兼容、版本是否对应、该更新哪一边，以便两边分别升级后不再遇到含糊的失败。             | 托盘启动后首次取得状态、切换发行版或修改 `webmux` 路径、安装完成后，以及处于缺失或不兼容状态时打开菜单，在后台以 `version --json` 检查（旧版本回退文本并视为契约 v1），单次不超过 30 秒，日志记录两侧版本与契约；兼容只看控制契约，对应只比较版本号，`dev` 等非发布版本无法判断且不提示；结果只出现在菜单状态行，不发通知或弹窗：较旧一方、“比托盘新，请升级托盘”或“版本过旧，请升级”；WSL 较新且为发布版本时提供“下载托盘 <版本>”打开 Release 页面；契约不兼容仍可启动、停止、重启，以 Windows 侧可达性判断运行并显示“运行中（不兼容，功能受限）”，状态无法解析不判失败、不自动重启；缺少本机 API 时禁用启动；运行实例与已安装文件版本不同时提示重启后生效，只有托盘管理的实例可从菜单重启。                                                                                                                                            |
| US-O12 用安装程序安装与卸载托盘    | 作为 Windows 使用者，我希望用安装程序安装、升级和卸载托盘，以便获得固定位置、开始菜单入口和卸载项，而不必手工放置 exe。                            | `webmux-setup-windows-<架构>.exe` 按当前用户安装、不需要管理员，默认目录 `%LOCALAPPDATA%\Programs\WebMux`（可更改，升级沿用上次目录）；安装 `webmux-tray.exe`、开始菜单“WebMux”与“应用和功能”卸载项（名称、版本、发布者）；“安装选项”页的“开机后自动启动 WebMux”默认勾选，写入与托盘菜单“登录时自动启动”相同的启动项；预置同架构 Linux 服务端到托盘下载缓存，不访问或改动 WSL；安装包架构与 Windows 不符时提示正确的安装包并以退出码 2 退出，不写任何文件；覆盖安装先以 `quit` 关闭本用户托盘（WebMux 与会话保持），安装目录中的托盘 10 秒无响应才强制结束，其他位置不响应的托盘只提示用户退出并可重试，静默模式以退出码 3 结束且不写文件；完成后启动托盘；卸载同样先关闭托盘，删除程序、快捷方式、卸载项与预置服务端，登录启动项仅在指向本次安装时删除，保留托盘设置、日志与 WSL 中的 webmux，不停止 WebMux；支持 `/S` 静默安装与卸载。 |
| US-O13 开放到公共网络              | 作为 Windows 使用者，我希望在托盘中一键让 WebMux 监听所有网卡，以便需要时让其他设备访问，平时只监听本机。                                          | 服务报告网络状态时显示“开放到公共网络（监听所有网卡）”勾选项（旧服务不显示）；开启前确认明文 HTTP 与 Token 风险；经 `POST /local/v1/network` 只替换监听套接字，会话与连接不中断，Host 校验与状态链接随之更新；关闭回到配置地址（通配则改为 127.0.0.1）；选择存于 `listen-settings.json` 并优先于 TOML，`--listen` 只覆盖本次；存储故障时不能开启、关闭仍生效；会话内进程 403。                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

隧道设置的增量兼容同样归入 US-O11：不得从版本号或存在 `tunnel` 字段推断设置页可用，只有 `settingsAvailable: true` 才显示入口；缺少该字段的旧服务仍保留原有隧道控制。可选 `enabled` 表示当前进程期望（包括 `--tunnel` 覆盖），不是持久磁盘值；缺失时才按 starting/ready 推断开关。

Windows 原生终端客户端复用 US-M01–US-M06：提供 run、attach、ls、open、status 与 version，服务仍在 WSL 中。

- 发行版与 webmux 路径：按命令行、环境变量、托盘设置、默认值依次解析。
- 路径换算：用 `wslpath` 换算盘符路径，识别同发行版的 WSL UNC 路径，无法换算时要求显式 Linux `--cwd`。
- 连接：经 `wsl.exe --exec webmux bridge`，不依赖 localhost 转发。
- 附着：使用 UTF-8/VT 控制台，恢复后还原模式与代码页。
