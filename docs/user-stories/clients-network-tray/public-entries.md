# 公网与 tailnet 入口

本文件属于 [原生客户端、隧道与托盘](../clients-network-tray.md)。

## N. Cloudflare 公网隧道

| 编号 / 功能             | User story                                                                                                         | 验收要点                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-N01 临时公网入口     | 作为明确选择公网访问的部署者，我希望启用 Quick Tunnel，以便临时从无法接入 VPN 的设备连接自己的终端。               | 可在 Web 设置页保存 Quick 模式并确认启用，也可用 `--tunnel` 或 `[tunnel].enabled`；无需 Cloudflare 账号，获得随机 HTTPS 地址，不承诺固定地址或 SLA；未启用时不创建隧道。Web 设置在服务器 `<state_dir>/tunnel.json` 原子保存（目录 0700、文件 0600、独占锁），跨浏览器与重启生效并优先于 TOML 的模式、主机名、凭据及开关；显式 `--tunnel` 只覆盖当前进程开关，不改写磁盘。                                                                                                                |
| US-N02 固定域名隧道     | 作为已有 Cloudflare 配置的部署者，我希望使用 Named Tunnel，以便通过预设的公共主机名访问。                          | Web 页可保存 Named 模式、裸主机名及写入式隧道 token，并在 Cloudflare 配置回源；也支持 TOML 配置。省略 token 保留已有凭据，首次配置或显式空凭据不可保存 Named；切回 Quick 清除主机名与凭据；凭据不回显、不放入 URL 或浏览器持久存储，只显示是否已配置，经环境变量而非命令行传给 cloudflared；指定空配置避免本机其他 cloudflared 配置干扰。                                                                                                                                                |
| US-N03 隧道认证与扫码   | 作为部署者，我希望公网入口始终要求足够强的 token，并能扫码连接，以便明确控制入口凭据。                             | WebMux 登录 token 与 Cloudflare 隧道 token 不同；首次启动可生成并持久化 256 位随机登录 token，已有配置缺少登录 token 时生成本次进程的随机值；运行中启用要求当前登录 token 至少 43 字符，不生成或更换登录 token，条件不足提示修复后重启；显式 CLI/TOML 隧道启动仍校验登录 token。传统启动路径可输出含 token 链接与二维码，运行时启动只打印无 token 公网地址；持久化 token 重启保留，仅临时 token 重启更换，含 token 链接和二维码本身即授权入口，可能被启动日志保留。                      |
| US-N04 获取 cloudflared | 作为部署者，我希望自动定位或下载匹配的 cloudflared，以便不用手工管理隧道依赖。                                     | 按显式路径、PATH、状态缓存定位，不存在时下载固定版本；支持有序下载镜像，空镜像列表禁用回退；各来源均校验内置 SHA-256 后执行；定位或校验错误明确报出；路径和下载镜像等运维项仍由 TOML 管理，不由 Web 设置覆盖。                                                                                                                                                                                                                                                                           |
| US-N05 隧道故障隔离     | 作为使用者，我希望隧道断开时本机会话仍继续，以便恢复远程入口后继续任务。                                           | 隧道退出立即撤销对应公网来源授权，本地访问和 PTY 保留，不自动重试；Web 保存的启用状态在启动时遇到短登录 token、依赖下载或进程启动失败，只把隧道置为 failed，HTTP/本机 API 继续可用；设置文件损坏、不可读或锁冲突时保持原文件并禁止公网启动，不回退到 TOML/CLI 开启；关闭操作即使落盘失败也立即停止当前进程的隧道并撤销授权，返回 503 与 `notPersisted: true`，明确提醒修复存储后再重启，不能声称下次仍关闭；正常退出关闭隧道而不改持久开关。                                             |
| US-N06 在线切换隧道     | 作为浏览器或托盘使用者，我希望服务运行中开启或关闭公网隧道，以便控制入口而不中断会话。                             | Web 页与本机控制面共用持久化开关，启用前确认，要求已有至少 43 字符登录 token；成功保存后异步应用，无需重启，重复启用不产生第二个 cloudflared；更换已启用的模式、主机名或凭据先撤销旧授权并停止旧进程，再启动新配置，迟到事件不能恢复旧入口；普通保存/启用落盘失败不应用新设置，关闭例外见 US-N05。托盘仅在 `settingsAvailable: true` 时提供 Web 设置入口；勾选以可选 `enabled` 表示的当前进程期望（含 CLI 覆盖）为准，不等于磁盘开关或 ready，旧服务缺该字段时回退到 starting/ready。    |
| US-N07 配置说明与指南   | 作为不熟悉 Cloudflare 的使用者，我希望在设置页和文档中按步骤完成 Named Tunnel 配置，以便独立获得固定域名入口。     | 设置入口打开 `/settings/tunnel`，区分 Quick/Named，显示配置来源、凭据是否已配置、启用前提与存储问题；保存与启用分开，提供 Named 配置步骤、文档链接和写入式凭据框，不读取真实凭据；恢复配置文件默认值前确认，成功后删除 Web 覆盖并停止当前隧道，不立即按 TOML 自动开启，下次启动才遵循 TOML；恢复失败不假装成功；文档覆盖 Windows/WSL、验证、排错与安全。                                                                                                                                 |
| US-N08 查看隧道运行状态 | 作为部署者，我希望在设置页看到当前公网隧道的运行状态、模式与主机名，以便确认隧道是否启用时不必查看托盘或服务日志。 | 独立显示当前进程期望 `enabled` 与 off/starting/ready/failed，启动失败仍可保留启用期望，不能把它当成可用公网入口；状态轮询反映托盘和其他设备变化，ready 才显示无 token 公网地址；只读 `/api/config` 的旧 `tunnel.enabled` 仍仅表示 starting/ready，模式和主机名动态跟随有效设置，推送资格按当前有效 HTTPS 入口（含 Named Tunnel、Tailscale Serve/Funnel）与本机回环判定；GET 设置即使存储损坏仍可读状态及错误，不能启用时给出原因；接口不返回 Cloudflare 凭据，桌面和移动布局无横向溢出。 |

## P. Tailscale Serve / Funnel

| 编号 / 功能                    | User story                                                                                                                          | 验收要点                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-P01 检测 Tailscale 环境     | 作为部署者，我希望只读查看 Tailscale 是否可用、节点 DNS 与证书状态，以便判断能否使用自动 HTTPS 入口。                               | `GET /api/tailscale` 需要认证，返回 provider（linux/wsl-native/windows/none）、后端状态、节点 DNS、HTTPS 就绪、Funnel 属性、现有入口 host/port/public 与 WSL 网络模式；只执行 `status`/`serve status`/`funnel status`，短超时、无交互 stdin、缓存并合并并发请求；CLI 缺失、未登录、输出损坏或超时不 panic，也不把缺失字段当作已就绪；响应不含 token 或其他入口 target。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| US-P02 托管 Serve              | 作为部署者，我希望通过配置让 WebMux 在 tailnet 内提供自动证书的 HTTPS，以便手机等可信设备安全访问。                                 | `[tailscale] mode = "serve"` 在监听开始后以 argv 执行 `tailscale serve --bg --https=<port> http://127.0.0.1:<实际端口>`；执行前要求 `CertDomains` 包含节点 DNS；自动端口按 443、8443、10000 选择，显式冲突失败不覆盖；回读确认唯一 `/` handler 指向当前 target 且 `AllowFunnel` 为假后才登记来源并报告 ready；停止/失败只移除精确端口，绝不调用 reset。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| US-P03 显式 Funnel             | 作为明确需要公网访问的部署者，我希望显式启用 Funnel 并看到风险，以便在无 VPN 的设备上连接。                                         | `mode = "funnel"` 只允许 443/8443/10000，要求强 Token；不因检测到 Tailscale 就自动公开；命令失败把 stderr 映射为 HTTPS 未启用、缺少 funnel 属性、权限不足或端口冲突；回读 `AllowFunnel[host:port] == true` 后才登记公开来源；从 Funnel 切回 Serve 或端口变化先关闭旧精确目标，失败时确认不残留并保持 failed；设置页持续显示公网风险。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| US-P04 WSL NAT 阻塞            | 作为 WSL 使用者，我希望知道为什么不能托管 Windows Tailscale，并看到可行替代方案。                                                   | `provider = "windows"` 且 `wslinfo --networking-mode` 为 nat/unknown 时失败关闭，不执行任何 Windows 写命令；设置页与错误说明 mirrored（`.wslconfig` + `wsl --shutdown` 会结束会话）、WSL 内安装 Tailscale、Windows 托盘转发三种方案；不自动修改 `.wslconfig`、重启 WSL 或防火墙。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| US-P05 显式 Windows provider   | 作为 WSL 使用者，我希望显式选择 Windows 主机上的 Tailscale，以便在 mirrored 网络中使用 Windows 节点。                               | `auto` 只检测并优先正在运行的 WSL 原生 Tailscale，永不被用来代管 Windows；只有显式 `provider = "windows"` 才允许写命令，URL/Host/Origin 使用 Windows 节点 `Self.DNSName`；非 WSL 配置 windows 启动失败；权限不足提示在 Windows 管理员终端执行 `tailscale set --operator=<用户>`，不 sudo、不自动提权；WSL 关闭后保留的入口在下一次启动按状态文件对账。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| US-P06 所有权与失败关闭        | 作为部署者，我希望 WebMux 只清理自己创建的入口，并在无法确认时拒绝启动，以便不误改其他应用或暴露旧端口。                            | `<state_dir>/tailscale-ownership.json`（0600、原子替换、独立锁）记录 provider、DNS、模式、端口、target 与 pending/active；写命令前先落盘 pending，命令与回读成功后标记 active；`mode = off`、模式/端口/target/provider 变化或状态损坏时先对账，删除前用 `serve status` 复核 provider、DNS/端口与 target，读取失败则不删除并拒绝启动（错误给出状态文件路径），记录端口已无入口或改指其他 target 时判定记录过期、不动该入口并删除记录，无法移除旧入口则拒绝启动并给出精确的 `serve --https=<port> off` 命令；`serve off` 同时清除 Funnel 标记，重复移除视为成功；状态文件缺失或损坏但已有入口指向当前监听地址时仍视为所有权未知并拒绝接管，错误给出该入口端口与精确的 `serve --https=<port> off` 命令，供确认废弃后手工移除；绑定监听失败时关闭本次入口或报告风险；来源撤销后旧 Host 立即 403（若在 `allowed_origins` 手工保留了 ts.net 主机名，迁移时需删除），Cloudflare 与 Tailscale 可并存。 旧 tailscale.json 即使与新版记录并存也阻止启动，须先核实外部入口。 |
| US-P07 网页修改 Tailscale 设置 | 作为部署者，我希望在设置页修改 Tailscale 的模式、端口与 provider 并立即生效，以便不改配置文件、不重启服务就能开启、切换或关闭入口。 | `/settings/tailscale` 可选关闭/Serve/Funnel、端口（Serve 留空自动，Funnel 仅自动/443/8443/10000）与 provider（Windows 仅 WSL 显示）；`PUT /api/tailscale/settings` 保留认证与 Host 校验，按 TOML 规则校验后写入 `<state_dir>/tailscale-settings.json`（0600、原子替换、独立锁），之后启动优先于 TOML，`command` 只来自 TOML；保存后先撤销来源并移除不再符合新设置的本实例入口再应用，`starting` 期间页面轮询，移除失败保持 failed 且不应用新设置；从非 Funnel 切到 Funnel 前确认公网风险，未确认 400；登录 Token 少于 43 字符或监听不可托管时 409 且不保存，页面显示原因；从当前 Tailscale 地址替换入口前提示断线；恢复配置文件设置前确认，删除覆盖并关闭本实例入口，TOML 下次启动生效；设置文件损坏或被锁时禁止写入且托管保持关闭；会话内进程经本机 API 修改返回 403。                                                                                                                                                                                           |
